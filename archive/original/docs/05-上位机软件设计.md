# 第6章 上位机软件设计

本章主要介绍系统上位机软件的设计与实现。为配合双技术路线的验证需求，上位机软件同样分为两个独立版本：路线A采用Flask与Socket.IO构建Web仪表盘，侧重于深度学习模型的端到端推理与血压趋势展示；路线B采用Flask与SSE（Server-Sent Events）技术，侧重于心电信号的实时去噪监测与多参数同步显示。此外，本章还将详细说明下位机与上位机之间的通信协议设计。

## 6.1 路线A：Flask+Socket.IO Web仪表盘

路线A的上位机软件（对应代码`bp_web_v3.py`）主要承担PPG（光电容积脉搏波）信号的接收、深度学习模型推理以及血压数据的可视化展示任务。

### 6.1.1 技术栈与架构设计

该上位机采用前后端分离架构。后端基于Python Flask框架搭建，负责提供静态网页服务与RESTful API接口；前端采用HTML/JS/CSS构建，利用Chart.js库实现波形与趋势图的动态渲染。

为满足高频生理信号的实时传输需求，系统引入了Socket.IO实现全双工实时通信。下位机通过串口将PPG数据发送至PC端，后端Python脚本读取串口数据后，利用TensorFlow/Keras加载预训练的深度学习模型（UNetDS64 + MultiResUNet1D）进行推理，计算出收缩压（SBP）、舒张压（DBP）和平均动脉压（MAP）。随后，后端通过Socket.IO将原始波形与计算结果高频推送至前端页面，确保显示的低延迟与流畅性。

### 6.1.2 核心功能模块

路线A的Web仪表盘包含以下核心功能模块：

1. **实时波形展示**：前端页面顶部设有一个动态更新的折线图，用于实时绘制PPG波形。该图表支持自动滚动，帮助用户直观观察脉搏跳动状态。
2. **血压数值面板**：以醒目的大字体实时显示当前计算出的SBP、DBP和MAP数值，并根据血压范围辅以颜色提示（如正常为绿色，偏高为红色）。
3. **趋势折线图**：记录并绘制历史血压数据的变化趋势，便于用户观察一段时间内的血压波动情况。
4. **交互式校准界面**：由于深度学习模型存在个体差异，系统提供了一个校准面板。用户可输入水银血压计测得的真实血压值，系统会自动计算偏移量并更新内部校准参数，从而提高后续测量的准确度。
5. **数据导出功能**：支持将测量过程中的原始PPG波形与对应的血压计算结果导出为CSV文件，方便后续的离线分析与模型优化。

## 6.2 路线B：Flask+SSE实时去噪监测

路线B的上位机软件（对应代码`realtime_denoise/main.py`）主要用于验证心电（ECG）信号去噪算法的实时性能，并支持多参数生理信号的同步监测。

### 6.2.1 技术栈与架构设计

与路线A不同，路线B的上位机采用了Flask结合SSE（Server-Sent Events）的架构。SSE是一种基于HTTP的单向服务器推送技术，非常适合此类“服务器持续产生数据并发送给客户端”的场景。相比Socket.IO，SSE更加轻量，且在纯数据流推送方面具有更高的效率。

后端利用Scipy和Numpy库对接收到的原始ECG信号进行实时处理。系统维护一个固定长度的环形缓冲区，按批次（如每秒4次）将数据送入去噪算法模块（如FFT Gate），计算完成后再通过SSE推送到前端。

### 6.2.2 核心功能模块

路线B的实时监测界面侧重于信号质量的评估与多通道展示：

1. **双通道波形对比**：界面主图表同时绘制原始ECG信号（灰色线条）与去噪后的ECG信号（绿色线条）。这种叠加显示方式让用户能够直观地评估去噪算法对基线漂移和高频噪声的抑制效果。
2. **R峰实时标注**：在去噪后的波形上，系统会实时标注检测到的R峰位置。这对于后续计算脉搏波传导时间（PTT）至关重要。
3. **实时指标面板**：界面侧边栏动态显示当前信号片段的质量评估指标，包括峰值信噪比（PeakSNR）、RR间期互相关系数（mRR）以及波形平滑度（Smoothness）等。
4. **多通道扩展（V4版本）**：在最新的V4版本中，界面扩展为五通道同步显示，支持同时监测ECG、PPG、体温（TEMP）、血氧饱和度（SpO2）以及连续无创血压（cNIBP）推算结果，形成了一个完整的生命体征监测站。

## 6.3 通信协议设计

为确保下位机采集的数据能够稳定、高效地传输至上位机，系统针对两条路线的特点设计了不同的串口通信协议。根据硬件参数表，两者的通信波特率均设定为115200 bps。

### 6.3.1 路线A：文本协议

路线A仅需传输单通道的PPG信号，数据量相对较小。因此，采用了基于ASCII码的文本协议。

- **数据格式**：每包数据以`START
`作为起始标志，随后是多行以逗号分隔的传感器数据（如`时间戳,PPG数值
`），最后以`END
`作为结束标志。
- **设计考量**：文本协议的最大优势在于调试极其方便。开发人员可以直接使用串口助手查看明文数据，快速定位硬件采集或传输过程中的问题。虽然传输效率略低，但对于100Hz采样率的单通道PPG信号而言，115200 bps的波特率已完全足够。

### 6.3.2 路线B：二进制双包协议

路线B需要同时传输250Hz的ECG信号和100Hz的PPG信号，且对时间同步性要求极高。为此，设计了紧凑的二进制双包协议。

- **数据格式**：
  - **ECG数据包（13字节）**：以包头`0xAA`开始，包含时间戳、24位ECG采样值、Lead-off状态位，最后以CRC8校验码结束。
  - **PPG数据包（17字节）**：以包头`0xBB`开始，包含时间戳、红光与红外光采样值、体温数据，同样以CRC8校验码结束。
- **设计考量**：二进制协议去除了文本协议中的大量冗余字符，极大地提高了总线利用率。CRC8校验机制有效防止了传输过程中的误码导致波形畸变。双包独立发送的设计，使得不同采样率的传感器可以按各自的节奏上传数据，上位机再根据时间戳进行对齐，保证了PTT计算的时间精度。
